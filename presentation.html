02 · Introduction

Why automate reward design for dexterous hands?

  • Reward engineering is the bottleneck of RL — hand-tuned rewards need expert effort, and poor rewards silently cap policy quality.
  • Eureka [1]: a coding LLM writes reward functions from raw environment source code, refined by evolutionary search + reward reflection.
  • DrEureka [2]: extends this by LLM-generating domain randomization (DR) configs → zero-shot sim-to-real transfer.
  • Dexterous in-hand manipulation is the hardest testbed: high DOF (16–20 actuated joints), continuous multi-point contact, severe sim-to-real gap.
  • Training uses PPO [3] in massively parallel GPU simulation (Isaac Gym [10]) — thousands of environments per GPU.
  • Our aim: make the reward–DR loop self-diagnosing and adaptive, so it converges to rewards that transfer, not just rewards that score.

03 · Problem Statement

The reward loop is blind to physics

  • P1Static DR — DrEureka fixes DR ranges once, before training; policy robustness evolves, ranges don't (named a limitation by the authors themselves [2]).
  • P2No failure attribution — reward reflection reports that a reward failed, never why: reward-logic bug vs. physics/dynamics mismatch look identical to the LLM.
  • P3Risk of reward shunting — an unconstrained LLM "fixes" physics errors inside reward code, masking the true cause and hurting transfer.
  • P4Lossy feedback channel — hand-crafted per-component scalar statistics discard where and how trajectories fail.

Formal statement

Given task spec ℓ and environment M, jointly search reward R and DR distribution φ such that a PPO policy trained on (Mφ, R) maximizes true task fitness F on the real / held-out system — with failure feedback that separates physical mismatch from reward-logic error.

05 · Research Gaps

Four gaps at the intersection

G1DR never adapts inside the LLM loop

  • ADR [5] adapts but has no LLM rewards; DrEureka [2] has LLM rewards but static DR.
  • No work couples both to one feedback channel.

G2No physics-failure attribution

  • PINNs model manipulator dynamics [4], [8] — never used to tell an LLM why a reward fails.

G3Attribution never validated

  • No prior protocol tests a diagnosis signal against injected ground-truth faults (known reward bugs vs. known dynamics shifts).

G4Feedback channel is hand-crafted; single morphology

  • Reflection statistics are fixed heuristics, not learned.
  • Reward-generation systems rarely validated across two hand morphologies.

06 · Contributions

What this work adds

  • C1Adaptive DR in the reward loop — ranges widen/narrow every N reward iterations from policy performance, driven by the same feedback channel that edits rewards. (closes G1)
  • C2PINN failure diagnosis with routing — physics-residual signal classifies failures; reward-logic → reward edit only, physics mismatch → DR update only. Reward code is barred from absorbing physics errors. (closes G2)
  • C3Injection-validated attribution — known reward bugs vs. known dynamics perturbations give a ground-truth AUC for the diagnosis signal, plus shuffled-signal placebo arms. (closes G3)
  • C4Learned failure-mode summarizer — MLP trained to predict episode outcome + failure phase replaces hand-crafted reflection statistics. (closes G4, optional rung)
  • EvalCross-morphology ablation — full 4-rung ladder on Shadow Hand (20 DOF, sim suite) and LEAP Hand (16 DOF, sim + real hardware); one component changes per rung.

07 · Architecture (Abstract)

Two feedback loops, one diagnosis router

Router rule: each diagnosis can trigger only its own loop — reward code never compensates for physics mismatch.

08 · Module Split

Five modules, mapped to contributions

M1Reward generation loop (inherited)

  • Eureka pipeline unmodified: LLM → K candidates → parallel PPO → reflection.
  • Kept as-is for ablation validity (rung 1).

M2Adaptive DR controller (C1)

  • Performance-thresholded widen/narrow of DR ranges every N iterations.
  • Initialized from DrEureka's reward-aware physics prior.

M3PINN + diagnosis router (C2, C3)

  • MLP; supervised loss + physics residual (Lagrangian EOM, relaxed contact).
  • Contact-gated diagnostic signal; two-stage routing prompt; pre-trained frozen first.

M4Failure-mode summarizer (C4, optional)

  • Trained on free labels: episode success + hindsight failure phase.
  • Descriptors join the reflection channel; cuttable without breaking M1–M3.

M5Evaluation & transfer harness

  • 4-rung ablation ladder × 2 morphologies.
  • Injection calibration, placebo arms, routing audit.
  • Real LEAP Hand deployment; held-out "pseudo-real" sim for Shadow Hand.

09 · Dataset Description

Simulation-generated data, four corpora

  • No fixed offline dataset — all training data is generated online by GPU-parallel simulation (~4,096 environments per run, native control rate ≈ 60 Hz).
  • Environments
    • Shadow Hand [1], [10]: 24 joints / 20 actuated; Eureka's 29-task suite (9 Isaac + 20 bidexterous tasks).
    • LEAP Hand [2], [9]: 16 DOF; in-hand cube rotation; observations = 16 joint angles + proprioceptive history only (no object pose).
  • Rollout telemetry (per step): joint positions/velocities/torques, tracking error, contact events, active DR parameter values — feeds reflection + summarizer.
  • PINN corpus: privileged sim transitions — hand joint state + object 6-DoF pose/twist + DR params — sampled across DR ranges; physics residual is self-supervised (no manual labels).
  • Summarizer corpus: episodes auto-labeled success/failure by fitness F, plus hindsight failure-phase windows.
  • Injection corpus (ground truth for validation): labeled runs with seeded reward bugs (sign flip, wrong scale, missing term) vs. seeded dynamics shifts (mass ×1.5, friction ×0.3, added damping).
  • Real-world eval set: physical LEAP Hand rollouts — rotations per 20 s episode, zero-shot.

11 · Conclusion

Takeaways

  • Extends Eureka/DrEureka precisely where its authors flagged limits: static DR → adaptive, blind reflection → physics-attributed diagnosis.
  • The routing rule is the key safeguard — reward edits fix reward logic, DR updates fix physics, so the PINN's contribution stays measurable.
  • Validation is built in, not bolted on: injection ground truth, placebo arms, one-component-per-rung ablation, replicated across two hand morphologies.
  • Deliverables: adaptive reward-generation pipeline, validated diagnosis protocol (reusable beyond this system), zero-shot real LEAP Hand transfer results.
  • Future work: vision-based observations, online PINN retraining, extension to bimanual and deformable-object manipulation.

Immediate next milestones

  • Rung-1 reproduction on both platforms → injection calibration study (go/no-go for the PINN pillar) → LEAP Hand hardware build in parallel.
